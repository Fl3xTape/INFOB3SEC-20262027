0The mental model

The stack is ordinary memory. It is not magic and it is not a register. The CPU reads and writes it exactly like any other memory, using addresses held in ESP, EBP, or calculated from them.

EIP
next instruction
Points into executable code. EIP is a register, not a stack value. A return address is stored on the stack and later loaded into EIP by ret.
ESP
top of stack
Holds the lowest address currently used by the active stack. push makes ESP smaller; pop makes ESP larger.
EBP
frame base
A stable reference point for the current function. Locals are at negative offsets; arguments and the return address are at positive offsets.
Memory direction, in one sentence On x86 the stack grows downward: a push subtracts 4 from ESP and writes at the new, lower address. When we draw a stack, higher addresses are usually at the top and lower addresses at the bottom.

The classic frame layout

higher addresses
+----------------------+
| caller's frame       |
+----------------------+
| argument y           |  [EBP+12]
+----------------------+
| argument x           |  [EBP+8]
+----------------------+
| saved EIP / return   |  [EBP+4]   <-- ret reads this
+----------------------+
| saved EBP            |  [EBP]     <-- EBP points here
+----------------------+
| local variables      |  [EBP-4], [EBP-8], ...
+----------------------+
| ESP -> top of stack  |  lowest active address
+----------------------+
lower addresses

The four instructions that matter

push x    ESP = ESP - 4
         [ESP] = x

pop reg  reg = [ESP]
         ESP = ESP + 4

call f   ESP = ESP - 4
         [ESP] = return address
         EIP = f

ret      EIP = [ESP]
         ESP = ESP + 4

leave    ESP = EBP
         EBP = [ESP]
         ESP = ESP + 4

1How the stack is read

This is the part that usually causes confusion: most stack reads do not change ESP. An instruction such as mov edx, [ebp-4] simply computes an address and reads 4 bytes. Only instructions such as pop, ret, and leave move ESP as part of the read.

OperationChanges ESP?What actually happens
mov edx, [ebp-4] No Read 4 bytes at address EBP-4 into EDX. This is how a local variable is read.
mov eax, [ebp+8] No Read 4 bytes at address EBP+8. This is how a function argument is read.
mov [ebp-4], eax No Write EAX to memory at EBP-4. This is how a local variable is stored.
push eax ESP -= 4 Write EAX at the new ESP. The stack grows downward.
pop eax ESP += 4 Read the word at ESP into EAX, then move ESP up.
call add ESP -= 4 Push the return address (the instruction after call), then jump to add.
ret ESP += 4 Read the return address at ESP into EIP, then move ESP up.
leave ESP = EBP, then += 4 Throw away locals: set ESP=EBP, pop the saved EBP, leaving ESP pointing at the saved EIP.

Direct GDB proof: bytes, words, and little-endian

In the vars program below, after a=7 and b=3 have been stored, GDB prints the raw bytes starting at &b:

GDB — x/8bx &b (from gdb_vars.txt)
# command:
(gdb) x/8bx &b
0xffffdc40:  0x03  0x00  0x00  0x00  0x07  0x00  0x00  0x00
             └──── b = 3 ────┘  └──── a = 7 ────┘

# 4 bytes are read as one 32-bit int. x86 is little-endian:
# 03 00 00 00  =  0x00000003
# 07 00 00 00  =  0x00000007
Reading does not consume The word at &a is still on the stack after you read it. A mov read copies the value into a register; it does not remove it from memory. The stack only “moves” when an instruction explicitly changes ESP.

3Example 1 — variable declaration

    

      A local variable in C becomes a fixed offset from EBP. There is no “variable name”
      left at runtime: the compiler remembers that a lives at EBP-4
      and turns every use of a into a memory access at that address.
    


    

      

        
vars.c

        
/* compiled with:
   gcc -m32 -O0 -g -fno-pie -no-pie \
       -fno-stack-protector \
       -fno-asynchronous-unwind-tables \
       -mpreferred-stack-boundary=2
*/

int main(void)
{
    int a = 7;      // a lives at EBP-4
    int b = 3;      // b lives at EBP-8
    return a + b;
}

        

          GDB proves the offsets: p/x &a → 0xffffdc44,
          p/x &b → 0xffffdc40, while
          EBP = 0xffffdc48. Therefore a is EBP-4 and b is EBP-8.
        

      


      

        
Compiled assembly (Intel syntax)

        
; main prologue
08049152  push ebp
08049153  mov  ebp, esp
08049155  sub  esp, 0x8          ; room for a and b

; int a = 7;
08049158  mov  DWORD PTR [ebp-0x4], 0x7

; int b = 3;
0804915f  mov  DWORD PTR [ebp-0x8], 0x3

; return a + b;
08049166  mov  edx, DWORD PTR [ebp-0x4]   ; read a
08049169  mov  eax, DWORD PTR [ebp-0x8]   ; read b
0804916c  add  eax, edx                   ; result 10
0804916e  leave                           ; destroy frame
0804916f  ret                             ; return to caller

4Example 2 — going to a new method

    

      A function call is a jump plus bookkeeping. The caller pushes arguments, then
      call pushes the return address. The callee creates its own EBP frame.
      The old frame is not destroyed; it remains above the new one.
    


    

      

        
call.c

        
int add(int x, int y)
{
    int sum = x + y;    // x at EBP+8, y at EBP+12
    return sum;
}

int main(void)
{
    int a = 7;
    int b = 3;
    int result = add(a, b);
    return result;
}

        

          GDB inside add: EBP = 0xffffdc2c,
          &x = 0xffffdc34 (EBP+8),
          &y = 0xffffdc38 (EBP+12),
          and [EBP+4] = 0x08049187 (the return address pushed by
          call add).
        

      


      

        
Assembly (Intel syntax)

        
; add()
08049152  push ebp
08049153  mov  ebp, esp
08049155  sub  esp, 0x4
08049158  mov  edx, DWORD PTR [ebp+0x8]   ; x
0804915b  mov  eax, DWORD PTR [ebp+0xc]   ; y
0804915e  add  eax, edx
08049160  mov  DWORD PTR [ebp-0x4], eax   ; sum
08049163  mov  eax, DWORD PTR [ebp-0x4]
08049166  leave
08049167  ret

; main()
08049168  push ebp
08049169  mov  ebp, esp
0804916b  sub  esp, 0xc
0804916e  mov  DWORD PTR [ebp-0x4], 0x7   ; a
08049175  mov  DWORD PTR [ebp-0x8], 0x3   ; b
0804917c  push DWORD PTR [ebp-0x8]       ; push b first
0804917f  push DWORD PTR [ebp-0x4]       ; push a second
08049182  call 8049152 <add>             ; push return + jump
08049187  add  esp, 0x8                   ; caller cleans args
0804918a  mov  DWORD PTR [ebp-0xc], eax   ; result = return

5Reading values from arguments inside a method

    

      In 32-bit cdecl, arguments are pushed right-to-left. The call instruction
      then pushes exactly 4 bytes: the return address. The callee's prologue pushes the old
      EBP (another 4 bytes), so the first argument ends up at [EBP+8].
    


    

      The offset formula
      argument 1 = [EBP+8], argument 2 = [EBP+12],
      argument 3 = [EBP+16]. The 8-byte gap is: 4 bytes for the saved EBP and
      4 bytes for the saved return address. On 32-bit x86 the return address is 4 bytes, so
      the formula is 4 (saved EBP) + 4 (return address) = 8.
    


    

      

        
          
AddressGDB value in the add frameMeaning

        
        
          
0xffffdc2c0xffffdc48[EBP] — saved EBP from main

          
0xffffdc300x08049187[EBP+4] — return address into main

          
0xffffdc340x00000007[EBP+8] — argument x

          
0xffffdc380x00000003[EBP+12] — argument y

          
0xffffdc280x0000000a[EBP-4] — local sum after the add

        
      

    


    
Reading an argument, step by step

    
    
      
  1. The caller executes push b, so ESP becomes lower and [ESP]=3.
    2. 
      
  2. The caller executes push a, so ESP becomes lower again and [ESP]=7.
    3. 
      
  3. call add pushes the return address 0x08049187 at the new ESP.
    4. 
      
  4. add's prologue pushes the old EBP and sets EBP=ESP.
    5. 
      
  5. Now x = [EBP+8] and y = [EBP+12], as confirmed by GDB.
    6. 
      
  6. mov edx,[EBP+8] reads x into EDX. ESP does not change.
    7. 
      
  7. mov eax,[EBP+12] reads y into EAX. ESP still does not change.
    8. 
    


    

      Why the stack does not “run out” when you read
      The return address and arguments stay in place until the caller explicitly removes
      them. In this program the cleanup is add esp,8 after add
      returns. Even then, the old words remain in memory; ESP simply moves above them.
    

  


  
  

    
6Example 3 — how an array is made and read

    

      A local array is not a pointer variable. It is a contiguous block of bytes inside the
      current frame. The compiler reserves space in the prologue and turns
      arr[i] into an address calculation: base + i * sizeof(element).
    


    

      

        
array.c

        
int main(void)
{
    int arr[3] = {10, 20, 30};
    int i = 1;
    int pick = arr[i];
    return pick;
}

        

          GDB inside main: EBP = 0xffffdc48.
          &arr[0]=0xffffdc34, &arr[1]=0xffffdc38,
          &arr[2]=0xffffdc3c. The array is 12 bytes: three consecutive
          4-byte words.
        

      


      

        
Assembly (Intel syntax)

        
; main prologue
08049152  push ebp
08049153  mov  ebp, esp
08049155  sub  esp, 0x14               ; 20 bytes of locals

; int arr[3] = {10,20,30};
08049158  mov  DWORD PTR [ebp-0x14], 0xa   ; arr[0]
0804915f  mov  DWORD PTR [ebp-0x10], 0x14  ; arr[1]
08049166  mov  DWORD PTR [ebp-0xc],  0x1e  ; arr[2]

; int i = 1;
0804916d  mov  DWORD PTR [ebp-0x4], 0x1    ; i

; int pick = arr[i];
08049174  mov  eax, DWORD PTR [ebp-0x4]         ; EAX = i
08049177  mov  eax, DWORD PTR [ebp+eax*4-0x14]  ; EAX = arr[i]
0804917b  mov  DWORD PTR [ebp-0x8], eax         ; pick = EAX

; return pick;
0804917e  mov  eax, DWORD PTR [ebp-0x8]
08049181  leave
08049182  ret

      

    


    

      The array-index formula from the actual instruction
      mov eax,DWORD PTR [ebp+eax*4-0x14] means:
      address = EBP + (index × 4) - 0x14.
      With EBP=0xffffdc48 and index i=1:
      0xffffdc48 + 4 - 0x14 = 0xffffdc38. That is exactly
      &arr[1] in the GDB output.
